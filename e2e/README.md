# End-to-end flows

Playwright flows for the simulator. Expected values come from `docs/reference/` (the real-world
chapters) through `support/oracles.ts`, never from engine output. A mismatch is a finding to triage.

```bash
npm run test:e2e           # everything
npm run test:e2e:ch01      # queueing and performance math (docs/reference/01)
npm run test:e2e:ch02      # reliability patterns (docs/reference/02)
npm run test:e2e:ch03      # distributions (docs/reference/03)
npm run test:e2e:ch04      # discrete-event simulation (docs/reference/04)
npm run test:e2e:ch05      # traffic and workload patterns (docs/reference/05)
npm run test:e2e:ch06      # compute nodes (docs/reference/06)
npm run test:e2e:ch07      # network nodes and routing (docs/reference/07)
npm run test:e2e:ch08      # edges, protocols and network physics (docs/reference/08)
npm run test:e2e:ch09      # storage and databases (docs/reference/09)
npm run test:e2e:ch10      # caching (docs/reference/10)
npm run test:e2e:ch11      # replication, consistency and consensus (docs/reference/11)
npm run test:e2e:ch12      # sharding and partitioning (docs/reference/12)
npm run test:e2e:ch13      # messaging and streaming (docs/reference/13)
npm run test:e2e:ch14      # orchestration and infrastructure (docs/reference/14)
npm run test:e2e:ch15      # security and identity (docs/reference/15)
npm run test:e2e:ch16      # observability (docs/reference/16)
npm run test:e2e:ch17      # DevOps and delivery (docs/reference/17)
npm run test:e2e:ch18      # data infrastructure and AI (docs/reference/18)
npm run test:e2e:ch19      # real-time and media (docs/reference/19)
npm run test:e2e:ch20      # integration (docs/reference/20)
npm run test:e2e:ch21      # DNS and certificates (docs/reference/21)
npm run test:e2e:ch22      # failure semantics and chaos (docs/reference/22)
npm run test:e2e:ch23      # capacity planning and cost (docs/reference/23)
npm run typecheck:e2e
```

Each flow checks up to three things: THEORY (engine against the closed form), UI (what the user sees
against the same closed form or the engine), PARITY (UI against engine for the identical document).

| File                                   | Covers                                                                                                                                                                                                   |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `oracles.spec.ts`                      | The formulas themselves, against the numbers hand-computed in the chapters                                                                                                                               |

| `journeys/ch09-storage.spec.ts`        | S-01 to S-08: capacity = workers / service time, read vs scan cost, a store filling at rate x amplification x record size, cost ranking of store types, IOPS ceiling, connections by Little              |

| `journeys/ch11-replication.spec.ts`    | R-01 to R-08: follower staleness 1 - e^(-wL), strong-read wait, read-your-writes, read-only followers, quorum availability, failover window, quorum write cost (tracked)                                 |
| `journeys/ch12-sharding.spec.ts`       | SH-01 to SH-08: shard shares on a hash ring, Zipf hot shard, throughput bounded by capacity / share, 1/(N+1) key movement, missing key policy, hot-shard split, scatter-gather mu x H_n                  |

| `journeys/ch15-security.spec.ts`       | SEC-01 to SEC-06: authentication reasons, block rate and inspection cost, crypto cost, remote validation by Little, WAF/firewall/KMS/identity gaps (tracked)                                             |

| `journeys/ch17-delivery.spec.ts`       | D-01 to D-05: canary share, blast radius = weight x rate x time, time to collect canary samples, remote flag cost, deployment controller (decision)                                                      |
| `journeys/ch18-data-ai.spec.ts`        | W-01, T-01 to T-03, B-01, E-01: window count and size, LLM latency = tokens x time, Little for streams, sequential calls (tracked), batching (tracked), batch job backlog                                |
| `journeys/ch19-realtime.spec.ts`       | RT-01 to RT-05: held connections = min(offered, cap, RAM), push fan-out cost and delivered share, heartbeat cores and saturation, SFU/reconnect storm (decisions)                                        |
| `journeys/ch20-integration.spec.ts`    | INT-01 to INT-05: provider latency, serial availability, idempotency window and distinct keys, rate limit and webhook retries (decisions)                                                                |
| `journeys/ch21-dns.spec.ts`            | DNS-01 to DNS-09: weighted, failover, latency and geolocation answers, TTL caching and miss ratio, TTL-delayed failover (tracked), geo latency (tracked), certificates (decision)                        |
| `journeys/ch22-failures.spec.ts`       | F-01 to F-08: reject/blackhole/hang/degraded shapes, recovery policies, survivor load, layered retries (tracked), zone outage, cold restart (tracked), metastable failure (decision)                     |
| `journeys/ch23-capacity.spec.ts`       | CAP-01 to CAP-06: cost = price x count x multiplier, cost per request, servers needed, N+1 headroom, spot interruption (decision), cost chip in the page                                                 |

Chromium: uses the Playwright-managed browser if installed, else the cached headless shell
(`PW_CHROMIUM_PATH` overrides). Port: `E2E_PORT` (default 5290).

| 19  | A quorum acknowledgement makes every follower current at commit (W = N).
